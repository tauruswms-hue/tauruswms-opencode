Operación

Instalación de pruebas en la LAN

Paso a paso para instalar el sistema en un servidor Windows de la red interna, para que los key users hagan las pruebas.

Es una instalación sin proxy ni HTTPS, con las dos aplicaciones escuchando directo en la red: el WMS en http://<servidor>:5000 y el panel admin en http://<servidor>:5001/admin. El mismo paso a paso está en texto plano en INSTALACION_LAN.txt, en la raíz del proyecto, para llevarlo al servidor.

No es una instalación de producción. Usa APP_ENV=development porque con production la cookie de sesión solo viaja por HTTPS y por HTTP nadie podría iniciar sesión. El costo es que las contraseñas viajan sin cifrar dentro de la LAN: aceptable para pruebas. Para producción ver Puesta en producción.

No arrancar con python app.py ni python admin.py. Ese modo levanta el depurador de Flask abierto a la red y cualquiera en la LAN podría ejecutar código en el servidor. Las aplicaciones se sirven con waitress (pasos 7 y 8). Tampoco ejecutar scripts/crear_tablas.py ni scripts/crear_datos_ejemplo.py: son de desarrollo.

Los comandos se ejecutan en PowerShell abierto como Administrador, salvo los que usan < o > (crear las bases, respaldar y restaurar), que van en cmd.exe porque en PowerShell no funcionan.

1. Instalar lo necesario

  • Python 3.12 de 64 bits, con "Install for all users" y "Add Python to PATH".
  • MySQL Server 8, como servicio de Windows.
  • Git para Windows.
  • NSSM, para dejar las aplicaciones como servicios: nssm.exe (carpeta win64) en C:\herramientas\, agregada al PATH.
mkdir C:\taurus
mkdir C:\taurus\logs

2. Copiar la aplicación

git clone https://github.com/tauruswms-hue/tauruswms-opencode.git C:\taurus\app
cd C:\taurus\app
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt waitress

waitress no está en requirements.txt, por eso se agrega en el comando.

3. Crear las bases de datos

Los tres scripts crean cada base con sus tablas y datos iniciales. Desde C:\taurus\app, en cmd.exe:

mysql -u root -p < docs\migrations\create_admin_mysql.sql
mysql -u root -p < docs\migrations\create_wms_mysql.sql
mysql -u root -p < docs\migrations\create_intercambio_mysql.sql

Si mysql no se reconoce, usar la ruta completa, por ejemplo "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe".

Después crear el usuario de la aplicación, entrando con mysql -u root -p:

CREATE USER 'taurus'@'localhost' IDENTIFIED BY 'UNA_CLAVE_PROPIA';
GRANT ALL PRIVILEGES ON taurus_admin.* TO 'taurus'@'localhost';
GRANT ALL PRIVILEGES ON taurus_wms.* TO 'taurus'@'localhost';
GRANT ALL PRIVILEGES ON taurus_intercambio.* TO 'taurus'@'localhost';
FLUSH PRIVILEGES;

4. Configurar

Crear C:\taurus\app\conexiones.json con la contraseña del paso anterior en las tres secciones. El formato está explicado en Configuración de conexiones.

{
  "admin": {
    "engine": "mysql", "host": "localhost", "port": 3306,
    "user": "taurus", "password": "UNA_CLAVE_PROPIA",
    "database": "taurus_admin", "charset": "utf8mb4"
  },
  "wms": {
    "engine": "mysql", "host": "localhost", "port": 3306,
    "user": "taurus", "password": "UNA_CLAVE_PROPIA",
    "database": "taurus_wms", "charset": "utf8mb4"
  },
  "intercambio": {
    "engine": "mysql", "host": "localhost", "port": 3306,
    "user": "taurus", "password": "UNA_CLAVE_PROPIA",
    "database": "taurus_intercambio", "charset": "utf8mb4"
  }
}

Generar tres secretos, ejecutando este comando tres veces:

.venv\Scripts\python -c "import secrets; print(secrets.token_hex(32))"

Y crear C:\taurus\app\.env con un secreto distinto en cada línea:

APP_ENV=development
SECRET_KEY=<secreto 1>
ADMIN_SECRET_KEY=<secreto 2>
SECRET_SALT=<secreto 3>

5. Registrar las migraciones

Las bases recién creadas ya tienen todo. Este paso marca las migraciones como aplicadas, sin ejecutarlas, para que las próximas actualizaciones apliquen solo lo nuevo. Ver Schema y migraciones.

.venv\Scripts\python migrate.py --db admin --baseline
.venv\Scripts\python migrate.py --db wms --baseline
.venv\Scripts\python migrate.py --db intercambio --baseline

6. Crear el SUPERADMIN del panel

Ejecutar C:\taurus\app\superusuario-dist\superusuario.exe y crear el usuario desde su menú. Toma la conexión de conexiones.json. Es obligatorio: con esta forma de arranque el panel no crea ningún usuario por defecto. Ver ejecutable de superusuario.

7. Probar el arranque a mano

.venv\Scripts\waitress-serve --listen=0.0.0.0:5000 app:app

Abrir http://localhost:5000 en el servidor: tiene que aparecer el login. Cortar con Ctrl+C y probar el panel:

.venv\Scripts\waitress-serve --listen=0.0.0.0:5001 admin:app

Abrir http://localhost:5001/admin y entrar con el SUPERADMIN. Si alguno no arranca, el mensaje de la consola dice qué corregir.

8. Instalar las aplicaciones como servicios

Así arrancan solas cuando se reinicia el servidor.

nssm install TaurusWMS C:\taurus\app\.venv\Scripts\waitress-serve.exe
nssm set TaurusWMS AppParameters "--listen=0.0.0.0:5000 --threads=8 app:app"
nssm set TaurusWMS AppDirectory C:\taurus\app
nssm set TaurusWMS AppStdout C:\taurus\logs\wms.log
nssm set TaurusWMS AppStderr C:\taurus\logs\wms.log
nssm set TaurusWMS AppRotateFiles 1
nssm set TaurusWMS AppRotateBytes 10485760
nssm start TaurusWMS

nssm install TaurusAdmin C:\taurus\app\.venv\Scripts\waitress-serve.exe
nssm set TaurusAdmin AppParameters "--listen=0.0.0.0:5001 --threads=8 admin:app"
nssm set TaurusAdmin AppDirectory C:\taurus\app
nssm set TaurusAdmin AppStdout C:\taurus\logs\admin.log
nssm set TaurusAdmin AppStderr C:\taurus\logs\admin.log
nssm set TaurusAdmin AppRotateFiles 1
nssm set TaurusAdmin AppRotateBytes 10485760
nssm start TaurusAdmin

Si un servicio no arranca, el motivo queda en C:\taurus\logs\. Los archivos se rotan a los 10 MB porque las aplicaciones registran en nivel DEBUG. Para ver o reiniciar un servicio: nssm status TaurusWMS, nssm restart TaurusWMS.

9. Abrir el firewall para la LAN

New-NetFirewallRule -DisplayName "Taurus WMS" -Direction Inbound -Protocol TCP -LocalPort 5000 -Profile Domain,Private -Action Allow
New-NetFirewallRule -DisplayName "Taurus Admin" -Direction Inbound -Protocol TCP -LocalPort 5001 -Profile Domain,Private -Action Allow

Si el panel admin se va a usar solo desde el propio servidor, no crear la segunda regla. El puerto de MySQL (3306) no se abre.

10. Dejarlo listo para los key users

  1. Entrar a http://<servidor>:5001/admin con el SUPERADMIN.
  2. Crear la empresa (tenant) de pruebas.
  3. Crear un usuario del WMS por cada key user, con su rol.
  4. Probar desde otra PC de la red: http://<servidor>:5000.
  5. Cargar los maestros desde las pantallas de importación. Los CSV de la carpeta Importaciones/ sirven de modelo; el orden de carga está en Importaciones/LEEME.txt.

11. Actualizar durante las pruebas

Cada vez que haya correcciones para probar. Primero una copia de las bases, en cmd.exe:

mysqldump -u root -p --single-transaction --databases taurus_admin taurus_wms taurus_intercambio > C:\taurus\respaldo_AAAAMMDD.sql

Después la actualización, en PowerShell como Administrador:

nssm stop TaurusWMS
nssm stop TaurusAdmin
cd C:\taurus\app
git pull
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python migrate.py --db admin
.venv\Scripts\python migrate.py --db wms
.venv\Scripts\python migrate.py --db intercambio
nssm start TaurusWMS
nssm start TaurusAdmin

Para restaurar la copia si algo sale mal: mysql -u root -p < C:\taurus\respaldo_AAAAMMDD.sql.

12. Intercambio con otro sistema (opcional)

Si se usa Intercambio, crear una tarea en el Programador de tareas de Windows. También se puede disparar a mano desde la pantalla Intercambio del WMS.

CampoValor
ProgramaC:\taurus\app\.venv\Scripts\python.exe
Argumentosprocesar_intercambio.py
Iniciar enC:\taurus\app
RepetirCada 5 minutos, o lo que haga falta

Problemas frecuentes

SíntomaQué revisar
Desde otra PC no abre la páginaEl firewall (paso 9) y que el servicio esté corriendo (nssm status TaurusWMS).
El login vuelve siempre a la pantalla de ingresoQue el .env diga APP_ENV=development. Con production la sesión exige HTTPS.
Error de conexión a la baseUsuario, contraseña y nombres de base en conexiones.json. El archivo se relee solo cada 30 segundos: no hace falta reiniciar los servicios.
Un cambio en el .env no se aplicaReiniciar los dos servicios.

Para pasar a producción

Al terminar las pruebas hace falta APP_ENV=production, HTTPS delante de las dos aplicaciones, una cuenta de Windows sin privilegios para los servicios y bases limpias. Ver Puesta en producción.
