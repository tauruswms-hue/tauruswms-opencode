Arquitectura

Visión general

Cómo está organizado el código y qué pieza se ocupa de cada cosa.

Aplicaciones

Dos aplicaciones Flask independientes comparten el .env y la base taurus_admin:

  • app.py (puerto 5000): el WMS. Registra un blueprint por dominio y aplica autenticación y permisos en cada request.
  • admin.py (puerto 5001): el panel de administración. Registra el blueprint de modules/admin.py y usa su propia cookie de sesión (taurus_admin_session), porque ambas apps comparten host y las cookies no distinguen puertos.

Las páginas se renderizan en el servidor con plantillas Jinja2. Hay endpoints JSON para acciones AJAX puntuales (guardar, eliminar, probar conexión) y una API REST para integraciones.

Autenticación y sesión

  • Sesión basada en cookie. El login lee taurus_admin.usuarios junto con su tenant.
  • La sesión vence a las 8 horas (SESSION_MAX_AGE_SECONDS).
  • La pantalla de login descarta sesiones inactivas por más de 5 minutos (LOGIN_IDLE_TIMEOUT_SECONDS).
  • La cookie es HttpOnly, SameSite=Lax y, en producción, Secure.
  • Los formularios llevan token CSRF; si falta o venció, la respuesta es un 400 con un mensaje explicativo (JSON en pedidos AJAX).

Convenciones

  • El idioma del sistema es español: rutas, variables, mensajes y columnas.
  • Los nombres de las columnas de ID no son uniformes (id, id_pedido, id_cliente…): consultar la tabla real en modules/schema_generator.py antes de escribir una consulta.
  • Las contraseñas se guardan con hash scrypt (werkzeug.security).
