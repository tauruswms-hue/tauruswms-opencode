Roles y permisos

El acceso se define por ruta: cada rol tiene habilitado un conjunto de rutas del WMS.

Modelo

ElementoDóndeQué es
RolesTabla roles (taurus_admin)Catálogo de roles.
PermisosTabla roles_rutasPares (rol, ruta) habilitados.
Rutas asignablesROUTE_CATALOG en modules/schema_generator.py Rutas agrupadas por módulo. Admite comodines /* y *.

La asignación se hace desde el panel admin y vale para todos los tenants.

Verificación en cada request

  1. El middleware verificar_autenticacion_y_permisos (app.py) exige sesión válida.
  2. Recalcula las rutas permitidas del rol y las deja en session['rutas_permitidas'], por lo que un cambio hecho en el panel se aplica sin volver a iniciar sesión.
  3. Si la ruta pedida está en el catálogo y el rol no la tiene, se bloquea.

La consulta a taurus_admin se cachea por rol (modules/permisos_cache.py, PERMISOS_CACHE_TTL, 30 s por defecto). El panel admin invalida la caché de su proceso al modificar roles o rutas.

Casos especiales

CasoComportamiento

En las plantillas

El helper tiene_permiso_ruta está disponible en Jinja para mostrar u ocultar elementos según el rol:

{% if tiene_permiso_ruta('/pedidos/nuevo') %}
    ...
{% endif %}

Al agregar un módulo o una ruta

Agregar la ruta a ROUTE_CATALOG. Una ruta que no está en el catálogo queda accesible para cualquier usuario con sesión.
