Primeros pasos

Instalación

Cómo dejar el WMS y el panel admin corriendo en una máquina de desarrollo.

Requisitos

  • Python 3.10 o superior (probado con 3.12).
  • MySQL 8.

1. Entorno y dependencias

python -m venv .venv
.venv\Scripts\activate          # Windows  (Linux/Mac: source .venv/bin/activate)
pip install -r requirements.txt

copy .env.example .env          # Windows  (Linux/Mac: cp .env.example .env)

Editar .env (secretos de sesión) y conexiones.json (acceso a las tres bases). El detalle está en Configuración.

2. Crear las bases de datos

El sistema usa tres bases en MySQL: taurus_admin, taurus_wms y taurus_intercambio. Se crean con los scripts de docs/migrations/:

mysql -u root -p -e "source docs/migrations/create_admin_mysql.sql"
mysql -u root -p -e "source docs/migrations/create_wms_mysql.sql"
mysql -u root -p -e "source docs/migrations/create_intercambio_mysql.sql"

El procedimiento completo, con cada script y sus datos iniciales, está en Base de datos.

3. Ejecutar

python app.py     # WMS   — http://localhost:5000
python admin.py   # Admin — http://localhost:5001/admin

Usuarios

Los scripts de creación no traen usuarios ni tenants. El primer usuario del panel admin se crea con superusuario.exe; con él se ingresa al panel y se dan de alta los tenants y los usuarios del WMS.

Solo en desarrollo. Si admin.py arranca con la tabla de usuarios del panel vacía y APP_ENV no es production, crea el usuario admin con contraseña Admin@2024!. En producción no lo hace.
