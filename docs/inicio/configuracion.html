Primeros pasos

Configuración

Dos archivos configuran la instalación: conexiones.json, con el acceso a las tres bases, y .env, con el entorno y los secretos de sesión. Ninguno de los dos se sube al repositorio.

Conexiones a las bases (conexiones.json)

Un único archivo con una sección por base. Lo leen el WMS, el panel admin, migrate.py, generar_schema.py y procesar_intercambio.py.

El archivo está en la raíz del proyecto. Hay que completar las credenciales de cada base:

{
  "admin": {
    "engine": "mysql",
    "host": "localhost",
    "port": 3306,
    "user": "taurus_admin",
    "password": "...",
    "database": "taurus_admin"
  },
  "wms": {
    "engine": "mysql",
    "host": "localhost",
    "port": 3306,
    "user": "taurus_wms",
    "password": "...",
    "database": "taurus_wms"
  },
  "intercambio": {
    "engine": "mysql",
    "host": "localhost",
    "port": 3306,
    "user": "taurus_intercambio",
    "password": "...",
    "database": "taurus_intercambio"
  }
}

Secciones

SecciónBaseObligatoria

intercambiotaurus_intercambio Solo si se usa Intercambio.

Claves de cada sección

ClaveObligatoriaValores
engineNomysql (por defecto).
hostSíServidor de la base.
portNoNumérico. Por defecto, 3306.
userSíUsuario de la base.
passwordSíContraseña de la base.
databaseSíNombre de la base.
charsetNoPor defecto, utf8mb4.

Comportamiento

  • Es la única fuente. Las conexiones no se leen del .env ni de la base.
  • Si el archivo falta o está incompleto, la aplicación informa qué falta. En producción no arranca.
  • Los cambios se toman sin reiniciar. El archivo se relee cada 30 segundos; si cambió, la aplicación reconecta con los valores nuevos. Si en ese momento no se puede leer, sigue con las conexiones que ya tenía.
  • Otra ubicación. Para tenerlo fuera de la carpeta del proyecto, indicar la ruta en la variable de entorno TAURUS_CONEXIONES.

Las contraseñas están en texto plano. Restringir la lectura del archivo a la cuenta que ejecuta las aplicaciones, no copiarlo ni subirlo al repositorio (está en .gitignore), y usar para cada base un usuario de MySQL propio con los permisos mínimos.

superusuario.exe usa su propio archivo. El ejecutable de superusuario lee superusuario.json, que solo tiene la conexión a taurus_admin.

Entorno y secretos (.env)

Copiar .env.example como .env y completar.

VariableUso
APP_ENVdevelopment o production. En production las aplicaciones no arrancan si detectan contraseñas o secretos por defecto, o si falta el archivo de conexiones; la cookie de sesión se marca Secure.
SECRET_KEYFirma de la sesión del WMS.
ADMIN_SECRET_KEYFirma de la sesión del panel admin.
SECRET_SALTSalt de la aplicación.
TAURUS_CONEXIONESOpcional. Ruta del archivo de conexiones.
CONFIG_CACHE_TTLOpcional. Cada cuántos segundos se relee el archivo de conexiones (30 por defecto).
PERMISOS_CACHE_TTLOpcional. Cuánto se cachean las rutas permitidas de cada rol (30 por defecto).

Para producción, generar secretos aleatorios largos:

python -c "import secrets; print(secrets.token_hex(32))"
