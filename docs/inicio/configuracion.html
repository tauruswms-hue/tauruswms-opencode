Primeros pasos

Configuración (.env)

Variables de entorno que leen el WMS y el panel admin. La referencia versionada es .env.example; el .env real no se sube al repositorio.

Entorno

VariableValoresEfecto
APP_ENVdevelopment | production En production las apps no arrancan si detectan contraseñas o secretos por defecto, la cookie de sesión se marca Secure y el panel no crea el usuario admin inicial.

Base administrativa (taurus_admin)

Usuarios, tenants, roles y la tabla configuracion. Es la única conexión que se toma siempre del entorno.

VariableEjemplo
DB_ADMIN_ENGINEmysql | postgresql | sqlserver
DB_ADMIN_HOSTlocalhost
DB_ADMIN_PORT3306
DB_ADMIN_NAMEtaurus_admin
DB_ADMIN_USERtaurus_admin
DB_ADMIN_PASSWORD—

Base operativa (taurus_wms) e intercambio

Son solo valores de respaldo. La conexión real del WMS y de intercambio se lee de la tabla configuracion de taurus_admin (se edita desde el panel admin). Las variables de entorno se usan únicamente si la tabla no tiene valores.

BaseVariables
WMSDB_ENGINE, DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD, DB_CHARSET
IntercambioDB_INTERCAMBIO_ENGINE, DB_INTERCAMBIO_HOST, DB_INTERCAMBIO_PORT, DB_INTERCAMBIO_NAME, DB_INTERCAMBIO_USER, DB_INTERCAMBIO_PASSWORD, DB_INTERCAMBIO_CHAR_SET

Secretos de sesión

VariableUso
SECRET_KEYFirma de la sesión del WMS.
ADMIN_SECRET_KEYFirma de la sesión del panel admin.
SECRET_SALTSalt de la aplicación.

Para producción, generar valores aleatorios largos:

python -c "import secrets; print(secrets.token_hex(32))"

Cachés

VariableDefaultQué controla
CONFIG_CACHE_TTL30 s Cada cuánto se relee la tabla configuracion. Es lo que propaga al WMS los cambios hechos en el panel admin; si los valores cambiaron, se reinician el engine y los pools.
PERMISOS_CACHE_TTL30 s Cuánto se cachean las rutas permitidas de cada rol.

Si la base admin no responde al refrescar, se mantiene la última configuración conocida.
