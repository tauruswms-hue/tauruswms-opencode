Configuración de conexiones

conexiones.json tiene el acceso a las tres bases, con una sección por base. Lo leen el WMS, el panel admin, migrate.py, generar_schema.py, procesar_intercambio.py y superusuario.exe. No se sube al repositorio.

Es el paso que sigue a la creación de las bases. El resto de la configuración (entorno y secretos de sesión) está en Configuración General.

El archivo

conexiones.json está en la raíz del proyecto. Hay que completar las credenciales de cada base:

{
  "admin": {
    "engine": "mysql",
    "host": "localhost",
    "port": 3306,
    "user": "taurus_admin",
    "password": "...",
    "database": "taurus_admin"
  },
  "wms": {
    "engine": "mysql",
    "host": "localhost",
    "port": 3306,
    "user": "taurus_wms",
    "password": "...",
    "database": "taurus_wms"
  },
  "intercambio": {
    "engine": "mysql",
    "host": "localhost",
    "port": 3306,
    "user": "taurus_intercambio",
    "password": "...",
    "database": "taurus_intercambio"
  }
}

Secciones

SecciónBaseObligatoria
admintaurus_adminSí
wmstaurus_wmsSí
intercambiotaurus_intercambio Solo si se usa Intercambio.

Claves de cada sección

ClaveObligatoriaValores
engineNomysql (por defecto).
hostSíServidor de la base.
portNoNumérico. Por defecto, 3306.
userSíUsuario de la base.
passwordSíContraseña de la base.
databaseSíNombre de la base.
charsetNoPor defecto, utf8mb4.

Comportamiento

  • Es la única fuente. Las conexiones no se leen del .env ni de la base.
  • Si el archivo falta o está incompleto, la aplicación informa qué falta. En producción no arranca.
  • Los cambios se toman sin reiniciar. El archivo se relee cada 30 segundos; si cambió, la aplicación reconecta con los valores nuevos. Si en ese momento no se puede leer, sigue con las conexiones que ya tenía.
  • Otra ubicación. Para tenerlo fuera de la carpeta del proyecto, indicar la ruta en la variable de entorno TAURUS_CONEXIONES (ver Configuración General).

Las contraseñas están en texto plano. Restringir la lectura del archivo a la cuenta que ejecuta las aplicaciones, no copiarlo ni subirlo al repositorio (está en .gitignore), y usar para cada base un usuario de MySQL propio con los permisos mínimos.

superusuario.exe usa este mismo archivo. El ejecutable de superusuario se conecta con la sección admin de conexiones.json.
