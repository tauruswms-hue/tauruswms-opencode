Superusuario (exe)

superusuario.exe gestiona por consola los usuarios del panel admin y limpia su auditoría. No necesita Python instalado y es la forma de crear el primer SUPERADMIN en producción.

Es el paso que sigue a la creación de taurus_admin: el script de la base no crea usuarios, así que el primero se da de alta con este programa.

Trabaja sobre las tablas admin_usuarios y audit_logs de taurus_admin. No toca los usuarios del WMS (taurus_admin.usuarios), que se administran desde el panel.

Configurar la conexión

El ejecutable usa el mismo archivo de conexiones que las aplicaciones, conexiones.json, y se conecta con los datos de su sección admin:

{
  "admin": {
    "engine": "mysql",
    "host": "localhost",
    "port": 3306,
    "user": "taurus",
    "password": "...",
    "database": "taurus_admin"
  },
  "wms": { ... },
  "intercambio": { ... }
}

Con el .exe dentro de la instalación (superusuario-dist/) no hay que configurar nada: toma el conexiones.json de la raíz. Para usarlo en otra carpeta o en otro equipo, copiar conexiones.json junto al .exe o indicar su ruta con --config.

Claves de la sección admin:

ClaveObligatoriaValores
engineNomysql (default) | postgresql | sqlserver (sqlite no está soportado por el ejecutable)
hostSíServidor de la base.
portNoNumérico. Si falta, el del motor.
userSíUsuario de la base.
passwordSíContraseña de la base.
databaseSíNormalmente taurus_admin.
charsetNoPor ejemplo utf8mb4.

El archivo se valida completo, igual que en las aplicaciones: una sección o clave desconocida, una obligatoria vacía, la falta de la sección wms o un JSON mal formado detienen el programa con un mensaje que indica el problema.

Para usar otro archivo de conexiones:

superusuario.exe --config C:\ruta\conexiones.json

Orden en que se busca el archivo

  1. El indicado con --config.
  2. El de la variable de entorno TAURUS_CONEXIONES.
  3. conexiones.json junto al ejecutable.
  4. conexiones.json en la carpeta que contiene a la del ejecutable (la raíz del proyecto, si el .exe está en superusuario-dist/).

Al ejecutar el script con Python (python scripts/admin_superusuario.py), los pasos 3 y 4 se reemplazan por el conexiones.json de la raíz del proyecto.

Menú

OpciónQué hace
1 — Crear / ActualizarSi el usuario no existe, lo crea (rol por defecto ADMIN). Si existe y está activo, lo actualiza: lo que se deja en blanco, incluida la contraseña, conserva su valor. Si está inactivo, hay que reactivarlo antes con la opción 3.
2 — Dar de bajaBaja lógica: el usuario queda inactivo, no se borra.
3 — ActivarRevierte la baja.
4 — ListarTodos los usuarios, o filtrados por usuario, nombre o email.
5 — Limpiar auditoríaBorra los registros de auditoría del panel hasta una fecha, inclusive. Ver más abajo.
6 — SalirTambién con Ctrl+C.

Toda escritura pide confirmación (S/N) y se guarda en el momento. Si la base falla, se deshace la operación, se informa el error y el menú sigue disponible.

Limpiar la auditoría

La opción 5 borra de audit_logs los registros de la auditoría del panel hasta la fecha que se indique, inclusive. Sirve para que la tabla no crezca sin límite.

  1. Se ingresa la fecha con formato DD/MM/AAAA. No puede ser posterior a hoy.
  2. El programa informa cuántos registros se van a borrar.
  3. Pide el usuario y la contraseña de un SUPERADMIN activo, que autoriza la operación.
  4. Pide una confirmación final (S/N) y borra.

La limpieza queda registrada en la misma auditoría como una Baja en la sección Auditoría, a nombre de quien la autorizó, con la fecha hasta la que se borró y la cantidad de registros eliminados. Ese registro no se borra en la misma operación.

El borrado es definitivo. Los registros eliminados no se pueden recuperar; si hay que conservarlos, hacer antes una copia de la tabla audit_logs.

Validaciones

  • Rol: solo SUPERADMIN o ADMIN.
  • No permite dar de baja ni degradar al último SUPERADMIN activo.
  • Contraseña: mínimo 8 caracteres, se ingresa dos veces y no se muestra en pantalla.
  • Email opcional, con formato validado.

Seguridad

conexiones.json guarda las contraseñas de las bases en texto plano. No copiarlo ni subirlo al repositorio (está en .gitignore). Si se lleva el ejecutable a otro equipo, la copia del archivo debe tener permisos restringidos al usuario que opera el sistema.

Las contraseñas de los usuarios se guardan con hash scrypt, igual que en el login del panel.

Regenerar el ejecutable

Hay que regenerarlo al cambiar scripts/admin_superusuario.py o los módulos de los que depende (modules/db_config.py, sql_dialect.py, passwords.py):

pip install -r requirements-build.txt
python scripts/build_superusuario.py

Los archivos intermedios quedan en build/, que no se versiona.

Alcance de las pruebas. El ejecutable está verificado contra MySQL. PostgreSQL y SQL Server están soportados por el código, pero falta probarlos con el ejecutable.
