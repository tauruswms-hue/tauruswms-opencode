Base de datos

Creación de las tres bases del sistema en MySQL, con los scripts que trae el proyecto.

Solo MySQL. La instalación se documenta para MySQL 8, que es el motor con el que se trabaja. Los scripts de los otros motores existen en docs/migrations/, pero quedan fuera de esta guía.

Las tres bases

OrdenBaseContenidoScript
1taurus_admin Usuarios, tenants, roles, permisos y configuración. docs/migrations/create_admin_mysql.sql
2taurus_wms Datos operativos: maestros, stock, recepciones, pedidos. docs/migrations/create_wms_mysql.sql
3taurus_intercambio Interfase con sistemas externos. Solo si se usa Intercambio. docs/migrations/create_intercambio_mysql.sql

Cada página muestra el script completo, sus tablas y los datos iniciales que carga. El primer usuario se crea después, con superusuario.exe.

Procedimiento

Los scripts borran la base si ya existe. Cada uno empieza con DROP DATABASE IF EXISTS. Usarlos solo en una instalación nueva.

  1. Crear las bases, desde la raíz del proyecto: 
    mysql -u root -p -e "source docs/migrations/create_admin_mysql.sql"
mysql -u root -p -e "source docs/migrations/create_wms_mysql.sql"
mysql -u root -p -e "source docs/migrations/create_intercambio_mysql.sql"
  2. Cargar las credenciales de las tres bases en conexiones.json. Ver Configuración.
  3. Registrar las migraciones existentes como aplicadas, para que el runner no intente ejecutarlas sobre una base recién creada: 
    python migrate.py --db admin --baseline
python migrate.py --db wms --baseline
python migrate.py --db intercambio --baseline

Alternativa: generar y ejecutar en un paso

En desarrollo, el mismo resultado se obtiene sin el cliente mysql:

python generar_schema.py --engine mysql --execute --seed

Usa las conexiones de conexiones.json. Después hay que registrar las migraciones igual que en el paso 3.

Usuarios

Los scripts no crean usuarios ni tenants: no hay usuarios ni contraseñas por defecto.

  1. Crear el primer usuario del panel admin con superusuario.exe.
  2. Ingresar al panel admin con ese usuario y dar de alta los tenants y los usuarios del WMS.

Mantener los scripts al día

Los scripts se generan desde modules/schema_generator.py. Después de un cambio de schema hay que regenerarlos y actualizar estas páginas:

python modules/schema_generator.py --all
python docs/generar_scripts_bd.py

Más detalle en Schema y migraciones.
