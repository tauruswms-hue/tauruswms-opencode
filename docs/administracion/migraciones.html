Schema y migraciones

Dónde se definen las tablas, cómo se genera el DDL y cómo se aplican los cambios sobre una base existente.

Fuente de verdad

Las tablas y los datos iniciales se definen en modules/schema_generator.py:

EstructuraContenido
ADMIN_TABLESTablas de taurus_admin.
WMS_TABLESTablas de taurus_wms.
INTERCAMBIO_TABLESTablas de taurus_intercambio.
ADMIN_SEEDSDatos iniciales (roles, rutas por rol y configuración).
ROUTE_CATALOGRutas asignables a roles.

Herramientas

HerramientaPara qué
python modules/schema_generator.py --all Regenera los archivos SQL para los 4 motores: schema_{motor}.sql en la raíz y docs/migrations/create_{admin,wms,intercambio}_{motor}.sql. No toca ninguna base.
python generar_schema.py Genera y ejecuta el schema contra las bases de conexiones.json. Opciones: --execute, --drop, --seed, --dry-run, --admin-only, --wms-only.
python migrate.py Aplica las migraciones pendientes sobre una base existente.
python schema_app.py Interfaz gráfica del generador (puerto 5002). Solo desarrollo.

Migration runner (migrate.py)

Lee docs/migrations/*.sql en orden alfabético, salteando los create_*, y registra las aplicadas en la tabla schema_migrations.

python migrate.py                # pendientes sobre el WMS
python migrate.py --db admin     # sobre taurus_admin
python migrate.py --dry-run      # muestra qué aplicaría, sin ejecutar
OpciónEfecto
--db wms|admin|intercambioBase destino. Por defecto, WMS.
--engineFuerza el motor.
--dry-runLista las pendientes sin ejecutarlas.
--verboseMás detalle en la salida.
--baselineRegistra las pendientes como aplicadas sin ejecutarlas. Se usa después de crear una base nueva desde los create_*.sql.

Restringir una migración

Un archivo puede limitarse a un motor o a una base con comentarios en sus primeras líneas:

-- engine: mysql
-- db: admin
ALTER TABLE ...

Procedimiento para un cambio de schema

  1. Revisar las migraciones pendientes en docs/migrations/.
  2. Actualizar la definición en modules/schema_generator.py.
  3. Regenerar los SQL: python modules/schema_generator.py --all.
  4. Escribir la migración incremental en docs/migrations/ para las bases que ya existen.
  5. Probarla con python migrate.py --dry-run y luego aplicarla.

El CI lo controla. La integración continua falla si los schema_*.sql o create_*.sql versionados no coinciden con lo que genera --all.
