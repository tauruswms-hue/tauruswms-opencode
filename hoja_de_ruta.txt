FASE 2 — MULTI-ENGINE: SCHEMA PORTABLE (4-5 dias)
========================================================================
Objetivo: Que el WMS pueda instalarse con MySQL, PostgreSQL, SQLServer o SQLite
sin cambiar codigo Python. Los .sql de migracion se mantienen MySQL
pero el schema de arranque se genera desde Python.

  2.1 Generador de schema desde Python
  ----------------------------------------
  Crear: modules/schema_generator.py

  Funcion: generate_schema(engine) -> SQL script
    - Lee definicion de tablas desde un diccionario Python
    - Genera DDL compatible con el engine seleccionado:
      * AUTO_INCREMENT -> SERIAL/GENERATED/IDENTITY
      * TINYINT(1) -> BOOLEAN/BIT
      * ENUM -> CHECK constraint o VARCHAR+CHECK
      * COMMENT -> se omite (no portable)
      * ENGINE/CHARSET -> se omite
      * ON UPDATE CURRENT_TIMESTAMP -> se omite (trigger si necesario)
      * LONGTEXT -> TEXT
      * INT(11) -> INTEGER
      * AFTER column -> se omite

  Tablas a definir (orden de creacion por FK):
    Admin: admin_usuarios, tenants, usuarios, configuracion,
           roles_rutas, audit_logs
    WMS:   tipoubicacion, zonas, ubicaciones, categorias, unidades_medida,
           proveedores, clientes, rutas, transportes, transporte_rutas,
           clases_pedido, materiales, material_proveedor,
           material_presentaciones, stockcontable, pedidos_cabecera,
           pedidos_detalle, recepciones_cabecera, recepciones_detalle,
           omc, omc_contenedores, inventarios_cabecera,
           inventarios_detalle

  2.2 Adaptar db_config.py para init de schema
  -----------------------------------------------
  Agregar funcion: init_database(engine, db_name)
    - Genera schema via schema_generator
    - Ejecuta contra la BD target
    - Si es SQLite, crea archivo .db automaticamente
    - Si es MySQL/PostgreSQL, crea DATABASE si no existe

  Integrar con la UI de configuracion-db existente:
    - Boton "Inicializar base de datos" despues de testear conexion
    - Genera tablas + datos semilla basicos

  2.3 Datos semilla desde Python
  --------------------------------
  Crear: modules/seed_data.py
    - Datos iniciales para tipoubicacion, zonas, clases_pedido
    - Usar INSERT ... ON CONFLICT DO NOTHING (portable)
    - Ejecutar despues del schema

  2.4 Corregir queries raw en Python
  -------------------------------------
  modules/admin.py:557:
    Reemplazar "LIMIT %s OFFSET %s" por limit_sql() con offset
    (necesita extender limit_sql para soportar offset)

  modules/sql_dialect.py:
    Agregar limit_with_offset(n, offset=0) para SQL Server:
      OFFSET {offset} ROWS FETCH NEXT {n} ROWS ONLY
    Para MySQL/PostgreSQL/SQLite: LIMIT {n} OFFSET {offset}

  2.5 schema_generator.py funcional
  ---------------------------------------------------
  - Genera DDL multi-engine desde definiciones de tablas
  - CLI: python schema_generator.py --engine mysql|postgresql|sqlite
  - python schema_generator.py --all genera los 3 archivos

Entregable: App que crea su propia BD en MySQL/PostgreSQL/SQLite
desde la UI de configuracion. schema_generator.py funcional.

FASE 3 — FLUJO COMPLETO DE DEMO (3-4 dias)
========================================================================
Objetivo: Que el ciclo Receive -> Store -> Pick -> Ship funcione
sin errores de punta a punta.

  3.1 Verificar flujo Recepcion
  --------------------------------
  Pasos del flujo:
    1. Login -> Dashboard
    2. Crear material con codigo de barras
    3. Crear ubicacion (asociada a tipo + zona)
    4. Crear recepcion -> agregar items -> cerrar recepcion
    5. Verificar que se genero stock en StockContable
    6. Verificar que se genero OMC de recepcion

  Puntos de fallo conocidos:
    - recepciones.py al cerrar: genera movimientos "Saliendo/Entrando"
      Verificar que los INSERT usan la columna 'descripcion' correcta
    - omc.py al crear OMC desde recepcion: verificar columnas
    - stockcontable.py upsert_posicion: verificar que funciona con
      el nuevo nombre de columna

  3.2 Verificar flujo Pedido/Picking
  ------------------------------------
  Pasos del flujo:
    1. Crear pedido con items
    2. Verificar stock disponible
    3. Preparar pedido (masivo o individual)
    4. Verificar que se genero OMC de picking
    5. Verificar estados del pedido cambiaron

  Puntos de fallo conocidos:
    - pedidos.py: verificar que la busqueda de contenedores funciona
      con el nombre de columna 'descripcion' correcto
    - omc.py: verificar GROUP BY con la columna renombrada

  3.3 Verificar flujo Despacho
  -------------------------------
  Pasos del flujo:
    1. Filtrar pedidos preparados
    2. Marcar como despachado
    3. Verificar que el pedido quedo en estado Despachado

  Nota: despacho.py es minimal (84 lineas). No genera movimiento
  de stock al despachar. Para MVP, esto es aceptable.

  3.4 Verificar flujo Inventario
  --------------------------------
  Pasos del flujo:
    1. Crear inventario (por ubicacion, material, o todo)
    2. Contar items (AJAX por linea)
    3. Cerrar inventario
    4. Verificar ajustes de stock

  3.5 Verificar Import/Export
  -----------------------------
    - Importar materiales desde XLSX
    - Exportar materiales a CSV
    - Importar ubicaciones
    - Verificar que los datos importados aparecen en la lista

Entregable: Flujo completo Receive->Store->Pick->Ship verificado
y funcional. Cada paso documentado con screenshots.

         │

                    │

                    │

         │

         │
  Fase 7 (demo) <────┘ (validacion final)

  Notas:
    - Fase 2 (multi-engine) es la mas compleja pero NO bloqueadora

    - Fase 6 (tests) es opcional para la primera demo, recomendable
      para iteraciones posteriores.
